# 정합성 분석과 대형 언어 모델 피드백 기반 재현 테스트 생성

**Generating Reproduction Test Based on LLM Feedback with Alignment Analysis**

본 저장소는 **이슈 설명과 수정 전 코드베이스를 입력으로 받아, 이슈에 기술된 실패 원인과 정합한 재현 테스트를 생성하는 방법**의 구현 및 실험 결과를 포함한다.

기존 재현 테스트 연구에서 주로 사용하는 실패-통과(Fail-to-Pass; F→P) 기준은 테스트가 패치 전에는 실패하고 패치 후에는 통과하는지를 확인할 수 있지만, **해당 테스트가 실제로 이슈와 관련된 원인 때문에 실패했는지까지 보장하지는 않는다.**

본 연구는 이를 보완하기 위해 이슈 구조화, 결함 위치 추정, 시나리오 생성, 재현 테스트 생성, 실행 기반 정합성 평가, 대형 언어 모델(Large Language Model; LLM) 진단 기반 부분 재실행을 하나의 파이프라인으로 구성한다.

---

## 1. 논문 전체 내용 요약

### 1.1 연구 목적

본 연구의 목표는 단순히 F→P 조건을 만족하는 테스트가 아니라 다음 조건을 함께 만족하는 **이슈 정합 재현 테스트**를 생성하는 것이다.

1. 수정 전 코드에서 실제 버그를 재현할 것
2. 결함과 관련된 코드 영역을 실행할 것
3. 테스트의 오라클과 실패 원인이 이슈 설명의 의도와 정합할 것

이를 위해 생성된 테스트를 **버그 재현 → 결함 관련 코드 실행 → 이슈-테스트 정합성** 순서로 평가한다.

### 1.2 전체 파이프라인

파이프라인은 다음 단계로 구성된다.

| 단계                  | 처리 내용                                                       |
| ------------------- | ----------------------------------------------------------- |
| **① 이슈 추출**         | 이슈에서 식별자, 오류 단서, 기대·관찰 동작, 재현 절차 등을 추출                      |
| **② 코드 탐색 및 위치 추정** | 정적 검색, 호출 관계, TF-IDF, CodeBERT, LLM 관련성 평가를 이용해 의심 파일·함수 탐색 |
| **③ 시나리오 생성**       | 결함 위치, 입력, 실행 절차, 오라클을 포함한 재현 시나리오 생성                       |
| **④ 시나리오 검증**       | 대상 위치 존재 여부와 시나리오 품질을 평가하고 우선순위 결정                          |
| **⑤ 테스트 생성**        | 검증된 시나리오와 오라클을 기반으로 재현 테스트 생성                               |
| **⑥ 테스트 실행**        | 수정 전 코드에서 테스트를 실행하고 결과·커버리지·SBFL 정보를 수집                     |
| **⑦ 정합성 평가**        | 버그 재현, 코드 실행 범위, 이슈-테스트 의미 정합성을 순차 평가                       |

### 1.3 이슈 구조화

이슈 설명은 다음 세 가지 정보로 구조화한다.

* **관찰 동작(Observed Behavior; OB)**: 현재 버그 상태에서 발생하는 잘못된 동작
* **기대 동작(Expected Behavior; EB)**: 정상적으로 수행되어야 하는 동작
* **재현 단계(Steps to Reproduce; S2R)**: 버그를 발생시키기 위한 입력 및 실행 과정

이 정보는 이후 결함 위치 추정, 시나리오 생성, 오라클 생성 및 정합성 평가에 공통으로 사용된다.

### 1.4 결함 위치 추정

초기 결함 위치 추정에서는 다음 정보를 결합한다.

* 이슈 식별자와 파일·함수명 기반 정적 검색
* 추상 구문 트리(Abstract Syntax Tree; AST) 기반 1-hop 호출 관계 확장
* TF-IDF 기반 이슈-코드 유사도
* CodeBERT 기반 의미 유사도
* LLM이 평가한 이슈-코드 관련성
* 함수 크기, 수정 빈도, 마지막 수정 시점 등의 정적 메트릭

두 번째 피드백 반복부터는 스펙트럼 기반 결함 위치 추정(Spectrum-Based Fault Localization; SBFL)을 추가로 이용한다. Ochiai, Tarantula, DStar 등의 정보를 이용해 초기 결함 위치를 실행 결과에 따라 보정한다.

### 1.5 시나리오 기반 테스트 생성

테스트 코드를 바로 생성하지 않고 먼저 **재현 시나리오**를 생성한다.

각 시나리오에는 주요하게 다음 정보가 포함된다.

* 대상 함수 및 소스 파일
* 재현 입력과 실행 절차
* 기대 동작
* 오라클 유형과 기대값
* 시나리오 신뢰도

시나리오는 코드베이스에 실제 대상 위치가 존재하는지 확인한 뒤, 시나리오 품질 점수와 결함 위치 정보를 이용하여 우선순위를 결정한다.

테스트 생성에서는 **오라클 우선(Oracle-First)** 전략을 사용한다. 먼저 EB에 기반한 정상 동작을 오라클로 고정한 후 테스트 코드를 생성하여, 현재 버그 동작 자체를 기대값으로 사용하는 문제를 방지한다.

### 1.6 실행 및 정합성 평가

생성된 테스트는 수정 전 코드베이스에서 실행된다. 이후 다음 세 점수를 순차적으로 평가한다.

#### 버그 재현 점수 `s_b`

테스트의 실패 비율과 이슈의 실패 관련 핵심어가 실제 실패 결과에 나타나는 정도를 함께 평가한다.

```text
s_b = ω_b × |F| / (|F| + |P|)
    + (1 - ω_b) × kw_hit_ratio
```

#### 코드 실행 범위 `s_c`, `s_c'`

첫 번째 반복에서는 일반 라인 커버리지 `s_c`를 사용한다.

두 번째 반복부터 SBFL을 사용할 수 있는 경우에는 결함 의심도가 높은 코드에 더 높은 비중을 부여한 **SBFL 가중 커버리지 `s_c'`**를 사용한다.

#### 이슈-테스트 정합성 `s_a`

OB, EB, S2R에서 추출한 핵심 토큰과 생성 테스트의 테스트 이름 및 단언문에서 추출한 토큰 간 자카드(Jaccard) 유사도를 계산한다.

세 기준을 모두 만족한 테스트만 정합 테스트로 판정한다.

```text
s_b  ≥ 0.70
s_c  ≥ 0.60  또는  s_c' ≥ 0.60
s_a  ≥ 0.65
```

### 1.7 LLM 피드백 기반 부분 재실행

정합성 기준을 만족하지 못했다고 전체 파이프라인을 처음부터 다시 실행하지 않는다.

LLM이 실행 결과와 정합성 평가 결과를 분석하고 문제가 발생한 위치에 따라 필요한 단계로 돌아간다.

| 진단 결과                    | 재실행 위치        |
| ------------------------ | ------------- |
| 결함 위치 자체가 잘못됨            | 코드 탐색 및 위치 추정 |
| 오라클 또는 재현 전략의 근본 수정 필요   | 시나리오 생성       |
| 시나리오는 유효하지만 테스트 구현 수정 필요 | 테스트 생성        |

이를 통해 앞 단계의 유효한 결과를 재사용하면서 불필요한 LLM 호출을 줄인다.

### 1.8 보조 평가 지표

F→P 외에 생성된 테스트의 정합성을 분석하기 위해 다음 지표를 사용한다.

**검증 커버리지(Checked Coverage; CC)**는 테스트가 실행한 코드 가운데 최종 오라클 결과에 실제 영향을 미치는 실행 영역의 비율을 측정한다.

```text
CC(t) =
| L_exec(t) ∩ L_slice(t) |
---------------------------
       | L_exec(t) |
```

**패치 적중률(Patch Hit Rate; PHR)**은 정합 테스트가 실제 정답 패치가 수정한 코드 영역을 실행했는지를 측정한다. PHR은 정답 패치를 사용하므로 벤치마크 실험에서만 사용하는 사후 평가 지표이다.

# 3. 가중치, 임계값 및 설정값

## 3.1 이슈-코드 초기 랭킹 `R_init`

```text
R_init(f)
= γ × rel_LLM(f)
+ (1 - γ) × [
    α × sim_TF-IDF(f)
    + β × sim_CodeBERT(f)
  ]
```

| Parameter |   Value | Description |
| --------- | ------: | ----------- |
| `γ`       | **0.4** | LLM 관련성     |
| `α`       | **0.5** | TF-IDF 비중   |
| `β`       | **0.5** | CodeBERT 비중 |

따라서 최종 비중으로 환산하면 LLM 관련성 40%, TF-IDF 30%, CodeBERT 30%이다.

LLM 관련성은 1~5점 척도로 평가한 뒤 다음과 같이 `[0,1]`로 정규화한다.

```text
rel_LLM(f) = (s - 1) / 4
```

## 3.2 함수 수준 결함 의심도 `R_func`

```text
R_func(g)
= R_init(f) × [
    δ0
    + δ1 × size_norm(g)
    + δ2 × churn_norm(g)
    + δ3 × age_norm(g)
  ]
```

| Parameter |   Value | Description |
| --------- | ------: | ----------- |
| `δ0`      | **0.7** | 기본 파일 관련성   |
| `δ1`      | **0.1** | 함수 크기       |
| `δ2`      | **0.1** | 수정 빈도       |
| `δ3`      | **0.1** | 마지막 수정 시점   |

가중치 합은 `1.0`이다.

## 3.3 시나리오 종합 점수 `ScenarioScore`

두 번째 반복부터:

```text
ScenarioScore
= w0 × BaseScore
+ w1 × SBFL_norm
+ w2 × rel_LLM
```

| Parameter        | Iteration 1 | Iteration 2+ |
| ---------------- | ----------: | -----------: |
| `w0` — BaseScore |     **0.9** |      **0.7** |
| `w1` — SBFL_norm |     **0.0** |      **0.2** |
| `w2` — rel_LLM   |     **0.1** |      **0.1** |

첫 번째 반복에서는 실행 스펙트럼이 아직 없으므로 SBFL 가중치를 사용하지 않는다.

## 3.4 시나리오 기본 점수 `BaseScore`

```text
BaseScore
= λ1 × q_oracle
+ λ2 × q_s2r
+ λ3 × q_target
```

| Parameter |   Value | Description |
| --------- | ------: | ----------- |
| `λ1`      | **0.5** | 오라클 품질      |
| `λ2`      | **0.3** | S2R 충실도     |
| `λ3`      | **0.2** | 대상 위치 정확도   |

`q_oracle`은 시나리오 생성 시 LLM이 부여한 1~5점 신뢰도를 `(s-1)/4`로 정규화한다.

`q_s2r`은 이슈 S2R 핵심어의 **50% 이상**이 시나리오에 포함되면 `1`, 그렇지 않으면 `0`이다.

`q_target`은 시나리오의 대상 클래스가 이슈에서 식별된 대상 클래스와 정확하게 일치하면 `1`, 그렇지 않으면 `0`이다.

## 3.5 버그 재현 점수 `s_b`

```text
s_b
= ω_b × |F| / (|F| + |P|)
+ (1 - ω_b) × kw_hit_ratio
```

| Parameter |   Value |
| --------- | ------: |
| `ω_b`     | **0.5** |

즉, 실제 실패 비율과 실패 핵심어 일치도를 동일한 비중으로 사용한다.

## 3.6 정합성 판정 임계값

| Gate   | Metric                                              |      Threshold |
| ------ | --------------------------------------------------- | -------------: |
| Gate 1 | Bug reproduction `s_b`                              | **τ_b = 0.70** |
| Gate 2 | Line coverage `s_c` / SBFL-weighted coverage `s_c'` | **τ_c = 0.60** |
| Gate 3 | Issue-test alignment `s_a`                          | **τ_a = 0.65** |

최종적으로 다음 조건을 만족해야 정합 후보로 판정한다.

```text
s_b ≥ 0.70
AND
(s_c ≥ 0.60 OR s_c' ≥ 0.60)
AND
s_a ≥ 0.65
```

첫 번째 반복에서는 `s_c`, 두 번째 반복부터는 SBFL 정보를 이용할 수 있는 경우 `s_c'`를 사용한다.

## 3.7 SBFL 활성화 조건

SBFL은 충분한 실행 스펙트럼이 확보된 경우에만 활성화한다.

```text
|F| ≥ 1
AND
|P| ≥ 3
```

여기서 `F`는 수정 전 코드에서 실패한 테스트 함수 집합, `P`는 통과한 테스트 함수 집합이다.
